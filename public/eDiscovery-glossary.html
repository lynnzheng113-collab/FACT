eDiscovery 专业术语表

v1.3 · 2026-10-21 · 优先沿用 FACT 原型当前中英翻译；业务概念与产品对象按语境区分

面向技术人员的业务词汇速查：先理解律师／调查团队在做什么，再理解系统为什么需要这些功能。术语优先沿用当前 FACT 原型的可见中英翻译；业务语境的 Presentation 与产品语境的 Representation 分开说明。具体含义仍需结合案件、辖区和交付协议确认。

一、案件与调查背景

Matter
案件／事项

一个诉讼、内部调查、监管响应或合规审查项目的业务单元。系统里的工作空间、文档和权限通常都围绕一个 Matter 组织。

Internal Investigation
内部调查

企业调查员工行为、商业往来、舞弊、数据泄露或其他内部事件。重点不是先找“所有文件”，而是围绕调查问题建立证据范围。

Litigation
诉讼

争议已经进入法院程序。律师需要按请求和程序规则识别、保全、审阅并提交与争议事项有关的电子材料。

Regulatory Investigation
监管调查

监管机构要求企业说明情况或提交材料。交付范围、格式、时间和保密要求往往由监管机构或调查协议约定。

Compliance Review
合规审查

企业主动或被要求检查是否遵守法律、政策或合同义务，可能尚未进入诉讼，但数据处理逻辑与 eDiscovery 很相似。

Early Case Assessment (ECA)
早期案件评估

在大规模审阅前先估算数据量、风险、关键人员和潜在证据，帮助律师决定案件策略和后续投入。

二、人员、数据与证据来源

Custodian
数据保有人／相关人员

持有、控制或使用相关数据的人，不是“数据库管理员”。例如涉事员工、管理者、项目负责人或共享邮箱负责人。

Data Source
数据源

数据实际存放的地方，例如邮箱、电脑、手机、云盘、聊天系统、数据库或业务应用。

Preservation
证据保全

要求相关人员和系统暂停常规删除，先把可能与争议有关的数据保住。常见落实方式是发送 Legal Hold 通知。

Legal Hold
法律保全通知

律师或企业向相关人员发出的保全要求，提醒他们不要删除、修改或覆盖可能相关的资料。

Collection
数据采集

按已批准范围从原位置取得数据并安全保存，同时记录来源、时间、方法和例外。

Forensic Image
法证镜像

对存储介质做尽可能完整的副本，可能包含普通文件拷贝看不到的已删除空间等信息；它只是特定采集方法，不是每个项目都必须使用。

Chain of Custody
证据流转记录

记录证据从采集到交付经过了谁、什么时间、做了什么，用来证明材料来源清楚、过程可追溯。

Hash
哈希值／数字指纹

由文件内容计算出的字符串。内容变化通常会导致 Hash 变化，因此可用于校验完整性、识别重复文件和追踪处理链路。

Workspace
工作空间／案件空间

一个案件在 Relativity 中的独立工作区，里面集中放文档、搜索、审阅字段、权限和交付配置。

Processing Set
处理集

一次数据处理作业的配置和数据集合，记录输入范围、处理规则、去重方式以及作业状态。

三、筛选、审阅与法律判断

Relevance
相关性

材料是否与案件问题、调查主题或监管请求有关。相关性由律师／调查团队判断，不是系统单独决定的技术属性。

Responsive
应响／与请求相关

材料落入已经定义的证据范围或交付请求，需要进入审阅、标记或制作流程。

Privilege
法律特权

某些律师沟通或法律工作成果可能依法不应向对方披露。系统可以提供字段和筛选，但最终判断由律师负责。

Processing
数据处理

把原始数据解析、展开、提取、去重并转换成可搜索、可打开、可审阅的记录。

Deduplication
去重

识别内容相同的文件，减少重复审阅；但仍要保留来源和 Family 关系，不能简单地把所有副本都删掉。

Family
文件家族／关联文档组

一组有业务关系的文档，最常见是一封邮件和它的附件。Family 表示同组关系，不自动等于完整父子树。

dtSearch Index
dtSearch 索引

根据一个搜索规则建立的检索结构，为大量文本建立快速查找目录；它不是普通静态文档清单。查询索引时返回命中文档列表。

Search Set (Relativity Saved Search)
搜索规则（Relativity Saved Search）

保存搜索范围、条件、返回字段和排序的可重复运行定义。一个搜索规则可以包含多个搜索条件，也可以直接运行返回当前命中文档，并可作为 dtSearch 索引的构建来源。

Search Condition
搜索条件

搜索规则中的单条字段、运算符和值，例如“提取文本 / Extracted Text 包含 / Contains termination”。

Run Search Set
运行搜索规则

按当前文档状态执行搜索规则并返回命中文档列表；它不等同于构建或更新 dtSearch 索引。

Build Index
构建索引

按来源搜索规则创建或更新 dtSearch 索引。修改搜索规则不会自动修改已经构建的索引，需要重新构建。

Coding
编码／审阅标记

审阅员把判断写入结构化字段，例如相关／不相关、特权、主题、处理意见和评论。

Coding Panel
编码面板／审阅字段面板

审阅员在文档旁边填写判断的界面。它把相关性、特权、主题、处理意见和评论等字段集中起来，供律师逐份记录结论。

Batch
审阅批次

预先切好的一包待审文档任务，通常分配给某位审阅员或团队，用来控制工作量、领取状态和完成进度。

Review Queue
审阅队列

按项目规则持续向审阅员提供待审文档的任务入口。它可以动态产生任务，不等同于固定的一包 Batch。

Review Center
审阅中心

集中管理审阅任务、批次、进度和质量的工作区域，让项目负责人知道哪些文档待审、谁在处理以及是否有积压。

Viewer
文档查看器

展示文档内容、页面、附件和文本层的审阅界面。律师在这里阅读材料、缩放、滚动、高亮并确认文件是否正常加载。

四、EDRM 生命周期与案件规则

EDRM
电子取证参考模型

Electronic Discovery Reference Model，把电子证据工作概括为 Information Governance、Identification、Preservation、Collection、Processing、Review、Analysis、Production 和 Presentation 等阶段。这里的 Presentation 是 EDRM／法律业务阶段“证据呈示”，不是产品中某一份文件的 Representation（表示／文档表示）。

Information Governance
信息治理

企业在日常经营中管理数据的规则，包括保存期限、访问权限、分类和删除政策，是案件发生前的数据基础。

Identification
信息识别

先判断哪些人员、设备、邮箱、系统和时间范围可能包含相关数据，决定后续从哪里找。

Review
审阅

由律师或调查团队逐份查看材料，并判断相关性、特权、保密性和后续处理方式。

Analysis
分析

通过关系、主题、时间、语言或相似度等方法理解数据结构，帮助团队更快找到重要材料；分析结果仍需人工判断。

Presentation
证据呈示

把已确认的证据在听证、庭审、调查访谈或报告中展示给法官、监管人员或其他接收方。它描述的是证据如何面向接收方呈示的业务阶段，不是文件在系统中的查看或导出版本。

Discovery
证据开示／取证程序

法律程序中各方按照规则交换与争议有关的信息和证据。它不是单纯的文件搜索，而是有范围、义务和期限的程序。

Discover
发现／定位材料

在产品或业务语境中，指通过搜索、筛选和分析找到可能相关的文档；它描述的是“找到材料”的动作，不等于最终认定相关。

Legal Request
法律请求／监管请求

法院、监管机构或对方律师提出的材料和格式要求，决定什么范围的文档需要被识别、审阅和交付。

Meet and Confer
双方协商会议

诉讼双方在案件早期协商数据范围、搜索词、保全方式、交付格式和争议处理规则。

Scope
范围

案件中实际要处理的数据边界，例如哪些 Custodian、数据源、日期和主题包含或排除在外。

Proportionality
比例原则

数据收集和审阅的成本、规模应与案件争议的重要性、金额和证据价值相称，不能无限制地收集所有数据。

Defensible Process
可辩护流程

能够说明为什么这样保全、采集、筛选和交付，并能提供记录支持的流程，而不是只依赖“系统自动完成”。

五、搜索、结果集与数据人口

Review Population
审阅人口／待审文档集

被确定为需要律师或调查团队实际查看的一组文档。它通常来自搜索、筛选、去重和排除规则的组合。

Publish Population
发布人口／发布文档集

被发布到当前审阅工作区、审阅流程或下一阶段的文档集合。它表示“让这批文档可用”，不等于已经完成审阅。

Duplicate
重复文档

与另一份文档内容相同或高度相同的文档。系统会标记重复关系，但是否排除通常要结合来源和 Family 语境决定。

Exact Duplicate
完全重复

文件内容或处理 Hash 完全一致的副本。它可以减少重复审阅，但不能自动证明两个来源在业务上可以互相替代。

Near Duplicate
近似重复

内容大部分相似但并不完全相同的文档，例如同一份报告的不同版本；近似去重可能帮助发现版本变化。

Search Term
搜索词

律师或项目团队用来定位材料的词、短语、编号、人员名或其他条件，需要记录版本和使用依据。

Keyword Search
关键词检索

按一个或多个词查找文档文本或字段值，是最容易理解的检索方式，但可能受拼写、语言和文本质量影响。

Boolean Search
布尔检索

用 AND、OR、NOT 组合条件，控制结果必须同时满足、满足其一或排除某类词。

Conditional Search
条件检索

按日期、发件人、文件类型、Custodian、字段值等结构化条件筛选，而不只是搜索正文文字。

Concept Search
概念检索

按主题或语义查找与某个概念相关的文档，即使文档没有出现完全相同的关键词。

Email Threading
邮件线程

把同一封邮件往来中的重复引用和回复组织起来，帮助审阅员先看最有信息量的邮件。

Communication Analysis
沟通网络分析

从发件人、收件人和时间关系中观察人员之间的沟通网络，用于发现关键人物和异常联系。

Analytics
智能分析

对文档进行聚类、相似度、语言、主题或关系分析，目标是缩小人工审阅范围和提高定位速度。

Unique Hit
唯一命中

按指定统计口径，某个文档或 Family 中第一次、唯一一次被某个搜索词命中的结果，用于评估搜索词效果。

Family Group
文件家族组

标识哪些文档属于同一个邮件及附件组合。它说明组成员关系，不等于直接 Parent / Child 树。

Parent Document
父文档

直接包含或产生另一份文档的文档，例如带附件的邮件。Parent 是直接关系，不是整个 Family 的总称。

Child Document
子文档

由另一份文档直接带出或包含的文档，例如邮件附件或压缩包中的文件。

Include Family
包含文件家族

把命中文档的邮件、附件或其他 Family 成员一并加入结果，避免只审阅孤立的一页证据。

Sampling
抽样

从大批文档中抽取一部分进行检查，用于估计遗漏、验证搜索词或评估自动分类质量。

六、Relativity 审阅、字段与项目管理

Field
字段

文档记录上的一个信息项，例如相关性、特权、发件日期、Custodian 或 Bates 编号。

Choice Field
选项字段

预先配置好选项的字段，例如 Responsive / Not Responsive、Privileged / Not Privileged，帮助不同审阅员使用一致值。

Tag
标签

审阅员给文档加上的分类或判断标记，用来表示相关性、主题、风险或后续处理动作。

Comment
评论／审阅备注

审阅员写下的解释性文字，记录为什么做出某个判断，或提醒下一位审阅者关注什么。

Reviewer
审阅员

负责阅读文档并填写 Coding Panel 的人员，可能是律师、法律助理、调查人员或外包审阅团队。

Review Status
审阅状态

表示文档当前处于未开始、进行中、已完成、需要复核或被退回等状态。

Hot Document
关键文档／高价值文档

对案件特别重要、风险高或需要优先处理的文档，通常由律师或项目负责人标记。

Issue Coding
争议点编码

把文档与案件中的具体争议点、事实主题或法律问题关联起来，便于后续分析和引用。

Privilege Log
特权日志

对不交付但主张法律特权的文档保留说明，通常包括日期、参与人、文档类型和不披露理由。

Second-Level Review
二级复核

由更资深的律师或质量团队复查初审结果，重点关注特权、重大风险、关键文档和不一致判断。

Escalation
升级处理

审阅员遇到不确定、敏感或高风险文档时，将其转交给指定律师或专家决定。

Audit Trail
审计轨迹

记录谁在什么时候查看、修改、标记、导出或制作了文档，用来证明处理过程可追溯。

Document Control Number
文档控制编号

系统中用于唯一识别一条文档记录的编号，常用于搜索、任务分配、沟通和交付追踪。

Document Set
文档集

按搜索结果、条件或项目规则组织的一组文档，可以作为审阅、分析、发布或制作的输入。

Permission
权限

控制用户能看什么、改什么、导出什么。法律项目通常需要区分律师、管理员、审阅员和外部接收方。

Batch Priority
批次优先级

决定哪一批文档先分配给审阅员，例如先处理关键 Custodian、时间敏感材料或高风险主题。

QC Sampling
质检抽样

从已审阅或已制作的结果中抽查一部分，检查标签一致性、遗漏、遮盖和格式问题。

七、数据处理、脱敏与交付细节

Native File
原始文件／原生文件

保留原来格式的文件，例如 DOCX、XLSX、PPTX、MSG 或原始音视频文件。原型查看器标签使用“原生 / Native”，导出语境使用“原始文件 / Natives”。

Representation
表示／文档表示／文件表示

产品语境中，同一份文档可有多个可查看或交付的文件表示，例如 Native、Image、Extracted Text、PDF。原型中的“输出表示 / Output representations”“文件表示 / File representations”和“跨表示泄漏检查 / cross-representation leak checks”都指这个对象；它不是 EDRM 的 Presentation。

Image File
图像文件／图像

把文档页面固定成 TIFF 或 PDF 等图像格式，方便在交付时保持页面外观一致；原型查看器和导出设置均使用“图像 / Image(s)”。

Text File
文本文件／提取文本

与文档关联的可检索文字版本；原型中查看器、字段和文本优先级统一显示为“提取文本 / Extracted Text”。

Structured Data
结构化数据

已经按字段和记录组织的数据，例如数据库表、交易记录或系统导出报表。

Unstructured Data
非结构化数据

没有统一表格结构的内容，例如邮件、文档、聊天记录、图片、音频和视频。

Container File
容器文件

里面还包含其他文件的载体，例如 PST、ZIP 或邮件归档；处理时通常需要展开其内容。

De-NIST
排除常见系统文件

使用已知文件清单排除常见软件和操作系统文件，避免把没有案件价值的内容送入审阅。

Extracted Text
提取文本

从电子文件内部读出的文字，用于搜索、预览和审阅；它不一定等同于原始文件的完整显示效果。

Exception
处理例外

文件因损坏、加密、格式不支持或权限问题没有按预期处理，需要单独记录和补救。

Password-Protected File
受密码保护的文件

没有密码无法打开或读取的文件，通常需要客户补充凭据或决定如何处理。

Corrupted File
损坏文件

文件无法正常打开或解析，可能需要重新采集、修复或作为处理例外交给律师决定。

Redaction Reason
遮盖理由

说明为什么遮盖某段内容，例如个人信息、商业秘密、法律特权或监管要求，便于复核和解释。

Burn-in
烧制

把遮盖、编号或标识真正合成到输出图像或版面中，避免接收方通过文本层或其他版本看到被遮盖内容。

Export
导出

按照确认的范围和格式生成交付文件包。导出不只是下载文件，还要保证字段、页面和关联文件能被接收系统正确读取。

Production Protocol
交付制作协议

约定交付格式、编号规则、字段、图像要求、原生文件规则和特殊处理方式的说明。

Production Volume
制作卷／交付批次

一次交付中包含的一组文档和页码范围，用于分批提交、追踪和核对。

Bates Prefix
Bates 前缀

加在 Bates 编号前面的案件或交付标识，用于区分不同案件、来源或制作卷。

Confidentiality Legend
保密标识

印在交付页面上的保密级别或使用限制，例如 Confidential 或 Highly Confidential。

Delivery Package
交付包

包含图像、原生文件、文本、DAT、OPT 和必要说明文件的完整输出集合。

Production Validation
制作校验／交付验证

在运行制作前及导出后检查范围、文件数量、页数、编号、字段、表示版本、链接、遮盖和可打开性；原型按钮使用“运行制作前校验 / Run pre-production validation”。

八、脱敏、交付与质检

Redaction
遮盖／涂黑处理

在仍要交付的文件上隐去个人信息、账号、联系方式、商业秘密等内容，同时保留其余证据价值。

Redaction Markup
遮盖标记

审阅界面里标出要遮住的区域或文字。标记本身还不等于安全交付，必须在正式制作时烧制到输出文件。

Production
正式制作／交付制作

按约定规则把获批文件生成固定、编号、可交付的版本，不是普通下载或导出列表。

Production Set
制作集

一次正式制作所使用的文档范围、编号规则、数据来源、输出格式和作业状态的集合。

Burn-in / Branding
烧制／版面标识

把遮盖、页码、Bates 编号、保密标识等真正合成到交付版面中，让接收方看到的是固定版本。

Bates Number
贝茨编号／交付页码

按顺序印在正式交付页面上的唯一编号，方便律师、法院或监管方精确引用某一页。

Load File
加载文件／导入索引文件

告诉接收系统每条文档的字段是什么、文件在哪里、页面如何对应的结构化文件。

DAT / OPT
DAT 字段文件／OPT 图像对应文件

DAT 通常携带文档字段和生产编号；OPT 通常说明图像页属于哪份文档，是交付包的目录和装配说明。

Quality Control (QC)
质量控制／质检

检查范围、文件可读性、遮盖、编号、格式和交付包完整性，确认没有明显遗漏或敏感信息泄露。

阅读边界：术语表是面向产品和技术团队的初步业务映射，不替代律师意见、案件协议或当地法律要求。系统负责让数据可处理、可检索、可审阅、可交付，相关性、特权和最终披露范围仍由律师／客户决定。
