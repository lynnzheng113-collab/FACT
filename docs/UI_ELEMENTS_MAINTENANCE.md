## 定位与环境

主表顺序为：一级模块 → 二级子模块 → 页面／业务视图 → 页面区域 → 元素名称（中英双语）→ 元素编号 → 类型 → 所在环境 → 后续关联。按同一层级分组排序；排序不改变编号。

环境是位置标签，不是权限或额外业务层级：

| 代码 | 名称 | 判定 |
| --- | --- | --- |
| SIGNED_OUT | 登录前 / Before sign-in | 未登录 |
| OUTSIDE_WORKSPACE | 未进入工作区 / Outside workspace | 已登录，未进入具体工作区 |
| INSIDE_WORKSPACE | 已进入工作区 / Inside workspace | 已进入某个 workspaceId |
| SHARED | 跨环境共用 / Shared across contexts | 同一个定义在多个上述环境使用；实例仍须指明实际环境 |

普通用户在工作区内的有效权限由管理员配置；角色仅作原型快照，权限规则另表关联。

## 每轮修改必须执行

1. 先读当前 Excel 的人工补充和登记 JSON，保存原件并按永久 ID 合并；不能用重扫结果覆盖人工内容。
2. 对比 `baseline.sourceSnapshot` 与当前源文件及 Git 差异。源码移动时先迁移旧身份；不以新文件位置、哈希或排序替换旧号。
3. CTL、ELM、PAGE、AREA、ACT永久ID保持；业务功能编号按已授权迁移映射统一。新增从同前缀最大号加一，只能单写入；删去的元素改为停用并记录原因，永不删除或回收编号。拆分/合并须记录前后关系。
4. 更新双语名称、页面区域、实例参数、事件、功能引用与源码位置；属性用元素 ID＋属性名，不给每个颜色/文案重复发号。
5. 先语义核对，再用 `node scripts/ui-elements.mjs snapshot` 刷新 `baseline.sourceSnapshot`；不可仅刷指纹绕过核对。
6. 执行 `node scripts/ui-elements.mjs check --source` 和 `node scripts/ui-elements.mjs check --previous <上版登记文件>`。新增或删除界面内容后检查扫描声明的去向，动态列表按定义＋对象键区分。
7. 有实质变化时在准备区生成下一版 Excel/说明/登记镜像，核对导出 ID、双语、分组列序和视觉，列迁移清单，再发布和归档旧版。同步 `current.json`。无变化不重复生成版本。
8. 提交/推送前的现有钩子会追加唯一性与源码同步检查；未获用户授权不提交或推送。

## 定时核查

Windows 计划任务 `FACT-UI-Element-Sync-Hourly` 每小时及用户登录时核查。本地监视 HEAD、源文件内容（包括未提交文件）与主登记；GitHub 监视 origin/main。后台使用锁，避免多实例并写；源文件持续变化时先等待下一轮。

有变化时由 Codex 执行上述增量核对，保留人工编辑；没有变化静默结束。失败保留旧版和 pending 状态，下轮重试；不将失败/无法识别身份的变更标为已同步。

GitHub 与本地同时有变化时分别列出来源，不能自动 pull/reset/checkout 覆盖本地。仅远程有新增时可只读 fetch/临时快照检查；不能把尚未合入本地的页面伪装成本地现状。必要时输出来源清晰的远程变更记录，并保持待合并状态。

电脑需开机且用户登录；后台使用当前 Codex 登录与模型配置。运行日志保存在维护目录的 runs；只有更新、失败或需要处理的变化记入通知摘要，不向他人发送消息。

暂停：`Disable-ScheduledTask -TaskName FACT-UI-Element-Sync-Hourly`；恢复：`Enable-ScheduledTask -TaskName FACT-UI-Element-Sync-Hourly`。
